# Database Schema Design

This document defines the authoritative schema for both the local SQLite database and the central PostgreSQL database. 

## Conventions
- **Money:** All monetary values are stored as `INTEGER` in the smallest currency unit (e.g., cents). `1250` means 12.50 ETB. Floating-point numbers are never used.
- **IDs:** Primary keys for sales and devices are `UUID` (string) to support offline generation and idempotent sync.
- **Snapshots:** `sale_items` stores the product name and price at the time of the sale. It does not reference the current product price.

## Tables

### 1. `users`
Individual accounts for owners and cashiers.
- `id` (UUID, PK)
- `username` (String, Unique)
- `password_hash` (String)
- `role` (Enum: OWNER, CASHIER)
- `is_active` (Boolean)
- `created_at` (Timestamp)

### 2. `products`
The catalog of items for sale.
- `id` (UUID, PK)
- `name` (String) e.g., "White Flour 50kg"
- `code` (String, Unique) e.g., "FLOUR-50"
- `category` (String) e.g., "Baking"
- `unit` (String) e.g., "Bag", "Kg", "Piece"
- `selling_price_minor_units` (Integer) e.g., 450000 for 4,500.00 ETB
- `is_active` (Boolean)
- `created_at` (Timestamp)
- `updated_at` (Timestamp)

### 3. `sales`
Completed transactions. Once written, this record is immutable. Reversals are handled by creating a new record in `sale_reversals`.
- `id` (UUID, PK) — Generated by the client device before sync.
- `receipt_number` (String, Unique) — Human-readable, generated locally (e.g., REC-20261021-001).
- `cashier_id` (UUID, FK -> users.id)
- `device_id` (UUID, FK -> devices.id)
- `subtotal_minor_units` (Integer) — Sum of line totals before discount.
- `discount_minor_units` (Integer) — Total discount applied.
- `total_minor_units` (Integer) — Final amount due.
- `amount_paid_minor_units` (Integer) — Cash received.
- `change_minor_units` (Integer) — Change given.
- `status` (Enum: COMPLETED, SYNCED)
- `created_at` (Timestamp) — Local time of sale.
- `synced_at` (Timestamp, Nullable) — When the server received it.

### 4. `sale_items`
The line items within a sale.
- `id` (UUID, PK)
- `sale_id` (UUID, FK -> sales.id)
- `product_id` (UUID, FK -> products.id)
- `product_name_snapshot` (String) — Name of the product at the time of sale.
- `unit_price_snapshot_minor_units` (Integer) — Price at the time of sale.
- `quantity` (Integer)
- `line_discount_minor_units` (Integer) — Discount applied to this specific line.
- `line_total_minor_units` (Integer) — (Unit price * quantity) - Line discount.

### 5. `audit_logs`
Append-only log of sensitive actions.
- `id` (UUID, PK)
- `user_id` (UUID, FK -> users.id)
- `action` (String) e.g., "PRICE_CHANGED", "SALE_VOIDED", "LOGIN_FAILED"
- `details` (JSON) — Snapshot of old vs new values.
- `created_at` (Timestamp)

### 6. `devices`
Authorized devices for licensing and sync.
- `id` (UUID, PK) — Generated locally on first run.
- `name` (String) — e.g., "Front Till Windows PC"
- `platform` (Enum: WINDOWS, ANDROID, IOS)
- `license_key` (String)
- `last_sync_at` (Timestamp)

- customer_name (String, Nullable) — Optional name of the buyer for record-keeping.
